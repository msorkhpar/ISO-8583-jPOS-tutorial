ISO-8583 messages are structured in a specific way to ensure standardized communication between financial systems. The message structure consists of three main parts: the Message Type Indicator (MTI), Bitmaps, and Data Elements.

Message Type Indicator (MTI)

The Message Type Indicator (MTI) is a four-digit code that defines the overall purpose and characteristics of the ISO-8583 message.

Four-digit structure

The MTI is always a four-digit numeric value. Each digit has a specific meaning:

  1. First digit: Version
  2. Second digit: Message Class
  3. Third digit: Message Function
  4. Fourth digit: Message Origin

Version, Message Class, Message Function, Message Origin

  • Version (1st digit):
    • 0: ISO 8583-1:1987
    • 1: ISO 8583-2:1993
    • 2: ISO 8583-3:2003
    • 3-9: Reserved for future use
  • Message Class (2nd digit):
    • 0: Reserved
    • 1: Authorization
    • 2: Financial
    • 3: File actions
    • 4: Reversal and chargeback
    • 5: Reconciliation
    • 6: Administrative
    • 7: Fee collection
    • 8: Network management
    • 9: Reserved for ISO use
  • Message Function (3rd digit):
    • 0: Request
    • 1: Response
    • 2: Advice
    • 3: Advice response
    • 4-9: Reserved for ISO use
  • Message Origin (4th digit):
    • 0: Acquirer
    • 1: Acquirer repeat
    • 2: Issuer
    • 3: Issuer repeat
    • 4: Other
    • 5: Other repeat

Bitmaps

Bitmaps are used to indicate which data elements are present in the message. Each bit in the bitmap represents a specific data element.

Primary bitmap

The primary bitmap is always present and indicates the presence of data elements 1 to 64.

Secondary bitmap

If bit 1 of the primary bitmap is set (1), it indicates the presence of a secondary bitmap. The secondary bitmap indicates the presence of data elements 65 to 128.

Tertiary bitmap (if applicable)

Some implementations may use a tertiary bitmap for data elements 129 to 192, although this is less common.

Data Elements

Data elements are the actual fields that contain the transaction data.

Field numbering (1-128 for primary, 129-192 for secondary)

  • Fields 1-64 are represented by the primary bitmap
  • Fields 65-128 are represented by the secondary bitmap
  • Fields 129-192 are represented by the tertiary bitmap (if used)

Data element presence indication

The presence of a data element is indicated by setting the corresponding bit in the bitmap to 1. If the bit is 0, the data element is not present in the message.

Practice: Building the primary bitmap

A bitmap is how an ISO-8583 message says which fields it carries. Section 2.2 describes it as eight bytes — sixty-four bits — written on the wire as sixteen hexadecimal characters. Bit n is set when data element n is present.

The counting is where this trips people up, and it trips them quietly. The bits are numbered from one, not from zero, and they are read most significant bit first. So data element 2 is the second bit of the first byte: 0100 0000, which is 40 in hex. Data element 11 is the third bit of the second byte. And bit 1 is not a data element at all — it is the flag that says a secondary bitmap follows, which is how a message reaches fields 65 to 128.

An off-by-one here does not crash anything. It produces a perfectly well-formed bitmap that describes a different message, and the first thing that notices is the system at the other end of the link.

Problem statement


The receiving side of a link never sees your ISOMsg: it sees bytes, and the bitmap is how it learns which data elements follow. Reading it wrongly shifts every field after the mistake, so the whole message parses as nonsense.


Write BitmapReader.present(String bitmapHex). It takes the bitmap part of a message as hexadecimal digits (either case) and returns, in ascending order, every data element it says is present.


  • The first sixteen digits are the primary bitmap. Bit n, counted from 1, most significant first, stands for data element n, from 2 to 64.
  • Bit 1 of the primary bitmap is not a data element. When it is set, a secondary bitmap of sixteen more digits follows, and its bit n stands for data element 64 + n, from 65 to 128. Only the primary's bit 1 is a flag: there is no tertiary bitmap here.
  • The length must agree with bit 1: sixteen digits when it is clear, thirty-two when it is set. Anything else, including a digit that is not hexadecimal, is refused with an IllegalArgumentException.
