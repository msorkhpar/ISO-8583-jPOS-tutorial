# Unpacking data elements

A message is a single string, and the fields inside it are not separated by
anything. Section 3.2 is the reason it can still be read: every data element
has a declared format, and the format says how long it is.

A fixed-length element simply occupies its length. A variable-length one
announces itself first — an LLVAR carries two digits of length before its
value, an LLLVAR carries three. So a reader walks the message from left to
right, and at each step it already knows how far to walk next. Get one length
wrong and everything after it is garbage, which is why a malformed message
usually fails somewhere other than where it is malformed.
