# Reading the MTI

Every ISO-8583 message opens with four digits, and those four digits are the
whole of its identity. Section 2.1 calls them the Message Type Indicator, and
each one answers a different question: which edition of the standard the
message is written against, what class of business it is, where in the exchange
it sits, and which side of the link sent it.

The tables are short enough to hold in your head. A `0100` is an authorization
request from an acquirer, written against the 1987 edition. Change the third
digit to a `1` and it becomes the response. Change the second to an `8` and the
message is no longer about money at all — it is the network asking whether
anybody is still listening.

That is the point of this first practice: an MTI is not opaque, and you do not
need a library to read one.

## Problem statement

Make `parts` in `practice/mti/Mti.java` return the four parts of an MTI — its
version, its message class, its message function and its message origin, in
that order — and refuse anything that is not four digits.

## Lesson: a practice whose grader already passes

The file ships finished, so its grader passes the moment you press Submit.
That is deliberate: the first thing worth knowing about a practice is what a
green run looks like, and you cannot recognise a broken one until you have seen
a working one. Press Run to see the file's own output, then Submit to see the
grader's.

Then break it on purpose. Delete a case from `messageClass`, submit again, and
read what the grader says. Put it back.
